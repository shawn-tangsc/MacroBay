# platform/ai

模型与智能体能力的平台层。九个目录，边界比名字重要——多数「该放哪儿」的争论都出在这里。

## 管什么

- `providers`（117 文件）：供应商预设、协议适配、模型目录、连接检查。**只有这里**知道某家供应商的端点形状。
- `chat`（15）：协议客户端（chat-completions / responses / messages / gemini）与 SSE 分帧。**只有这里**把字节流读成事件。
- `invocation`（5）：一次模型调用的编排——选模型、组请求、解析结构化输出。
- `model-defaults`（2）：默认模型（对话/快速/翻译/嵌入）的唯一解析入口。
- `assistant-platform`（60）：通用助手的实体、话题、消息树、流注册表与运行时。
- `agent-platform`（337）：智能体运行时、会话、工具、技能、工作流、审批、通道桥、产品工具包、评测、追踪。
- `web-search`（38）：搜索与抓取的供应商抽象（driver）、URL 安全、黑名单、截断。
- `session-context`（7）：一次会话发给模型的上下文的**纯契约与裁剪规则**——不读设置、不发请求。

`api` 是**预留**：`server.py` 占位、`routes/` 空目录。仓库里没有本地 HTTP API 服务。

## 不管什么（这一节比上一节重要）

- **不管业务语义。** 「哪些新闻值得看」「利率路径怎么判断」「这个来源该不该采」全部在 `products/<product-id>`。平台只提供机制，不知道「情报」是什么。
- **不管某个产品的能力开关。** 启停、就绪判断、额度，都是产品的判断；`platform/ai` 提供运行时，不提供策略。
- **不管凭据的存储。** 密钥在 `platform/secrets`；这里的 provider 视图只拿 `hasApiKey` 与掩码预览。
- **不管出网。** 所有请求经 `platform/network` 注入的 `platformFetch`；**这个模块里不该出现 `?? fetch` 之类的全局回退**，没有注入就报错，不许静默直连。
- **不管界面。** 没有 React、没有 i18n 词表、没有主题引用。文案在产品或壳的 i18n 里。
- **不管产品提示词。** 产品 Agent 的 prompt、skills、tools、workflows 在 `products/<product-id>/agents`；这里只有平台的通用运行时与内置工具。
- **不定义「对话该保留多少」。** `assistant-platform` 负责执行；「按 token 预算裁到多少」这类策略由 `session-context` 的规则决定、由调用方采用。

## 别人该怎么用它

1. **要调模型，走 `invocation` 或产品自己的客户端，但出网必须是注入的 `platformFetch`。** 自己 `new` 一个 HTTP 客户端就是绕过代理。
2. **要让某个产品能力对智能体可见，注册产品工具，不要改 `agent-platform`。** 产品工具通过生成注册表注入，平台里不应出现 `from 'products/...'`。
3. **要新供应商，改 `providers/providerPresets.ts` 这一处**；协议实现放 `chat`，UI 不显示协议与端点。
4. **要新的会话裁剪规则，改 `session-context`**，不要在助手或智能体里各写一份。
5. **想在这里加一个「只被某个产品用」的东西，先问一句：删掉那个产品之后，它还成立吗？** 不成立就说明它属于产品侧。

**用错了会怎样**：把产品语义塞进这里，第一个后果是删除 `products/<product-id>` 之后平台编不过——那把「可整块删除」的承诺当场作废；第二个后果是这里会开始出现只有某一方能理解的开关，下一个人加能力时会先找第二个开关的位置。
