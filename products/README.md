# Products

Product modules live here.

Each product should be removable without breaking the reusable platform foundation.

The shell discovers products by scanning:

```text
products/<product-id>/product.manifest.ts
```

If a product directory is added and contains a valid manifest, it can appear in the shell after registry generation.

If a product directory is deleted, it must disappear from the shell without any manual edits in `apps/desktop-shell`, `platform`, or other product registries.

Expected product shape:

```text
products/<product-id>/
├─ product.manifest.ts
├─ desktop/
│  ├─ pages/
│  │  └─ <page-id>/
│  │     └─ index.tsx
│  ├─ settings/
│  │  └─ <section-id>/
│  │     └─ index.tsx
│  ├─ widgets/
│  ├─ features/
│  ├─ entities/
│  └─ shared/
├─ service/
├─ agents/
├─ collectors/
└─ data/
```

Documentation ownership rule:

- Root `docs` is for public platform and product documentation.
- Product-specific design notes stay in the private development tree until they are ready for public docs.

## Registration Rule

`product.manifest.ts` is the only allowed registration surface for a product.

Use it to declare:

- shell menu pages
- shell settings sections
- service routes
- jobs
- migrations
- tools
- skills
- agents
- workflows

Do not add hand-maintained product lists elsewhere.

## Shell Contributions

Products contribute shell-visible UI through `shellContributions` in `product.manifest.ts`.

```ts
shellContributions: {
  menuPages: [
    {
      id: 'trades',
      title: { 'zh-CN': '交易复盘', 'en-US': 'Trade Replay' },
      icon: 'chart-candlestick',
      order: 20,
      module: './desktop/pages/trades'
    }
  ],
  settingsSections: [
    {
      id: 'risk-profile',
      title: { 'zh-CN': '风险偏好', 'en-US': 'Risk Profile' },
      icon: 'shield',
      order: 100,
      module: './desktop/settings/risk-profile'
    }
  ]
}
```

Product manifests should declare local IDs and local module paths only.

The generated registry step derives:

- global IDs such as `market-intelligence.insights`
- product routes such as `/market-intelligence/insights`
- shell-ready dynamic import entries

Directory and entry rules:

- Shell menu pages live under `desktop/pages/<page-id>/index.tsx`.
- Shell settings sections live under `desktop/settings/<section-id>/index.tsx`.
- Register pages with `module: './desktop/pages/<page-id>'`.
- Register settings sections with `module: './desktop/settings/<section-id>'`.
- Product settings sections are discovered by the shell settings workspace. They are not ordinary outer shell pages.

## Generated Registry

Generated files live under:

```text
products/generated/
```

These files:

- are generated by script
- must not be committed
- must not be edited by hand
- are the only product registry files that `apps/desktop-shell` and `platform` should consume

## What Not To Do

- Do not create hand-maintained product registry entry files such as `products/index.ts`.
- Do not directly import `products/<product-id>/...` from `apps/desktop-shell`.
- Do not directly import `products/<product-id>/...` from `platform`.
- Do not hand-write global routes or global contribution IDs inside product manifests.
