# 状态与限制

MacroBay 当前版本是 `0.4.5`。本文说明现在能用什么，以及目前故意不支持什么。

## 可以从源码使用

- 桌面 shell 可以通过 `pnpm dev` 启动。
- 可以添加、启用模型供应商并保存 API Key。
- 可以为智能体和助手选择默认模型。
- 智能体会话可以运行，并加载内置的 `market-intelligence` 产品。
- 看板、宏观日历、情报源配置和分析智能体都可以从产品内进入。
- 日报读的是已采集到本地的证据，可以从简报页生成。
- 智能体的结构化提问和工具审批会在对话中渲染。
- 仓库可以通过 `pnpm verify`。

## 本版本不可用

### 渠道集成

五个适配器（Telegram / Slack / Discord / QQ / 飞书）可以创建并启用，**但同一时刻只有一条通道是启用的**：
启用新的会自动关掉旧的；切换那一刻还没送达的那一条会留下「没送到：通道刚换」的记录，不会静默消失。
能收发的是**单聊消息**；群内 @ 和频道消息只部分验证过。**微信这一版还接不了**，这不是「以后能开」的占位。

### 官方 BLS 日历

官方 BLS 发布日历在当前网络环境无法获取：`www.bls.gov` 与 `api.bls.gov` 在 CDN 边缘直接返回 403，
走不走代理都一样。因此 BLS 日程与数值的自动同步已停用；库里已有的 BLS 事件来自上次成功同步，且
没有发布时间。美联储与 BEA 日历、以及行情侧日历不受影响。

### 打包安装程序

`pnpm build` 只生成 `out/` 下的 Electron bundle。macOS 的 `.dmg` 可以用 `pnpm dist:mac` 从源码
构建，但未签名、未公证，从网络下载的副本需要两步放行：**右键点应用 → 打开**（直接双击会被拒），
或执行 `xattr -dr com.apple.quarantine /Applications/MacroBay.app`。Windows 安装器同样未签名：
SmartScreen 显示「Windows 已保护你的电脑」，用户选择**更多信息 → 仍要运行**。这两个提示在
**每次下载更新后都会重现**，不只是第一次安装。Windows 的打包已配置，安装器既能由 CI 构建、也能在
Windows 11 x64 真机上构建产出，但安装后的运行态未做真机安装验收（缺 Windows 环境）；Linux 尚未配置
打包。也没有自动更新通道。
详见[打包](../development/packaging.zh-CN.md)。

## 平台支持

- **macOS**：arm64 安装包可以构建并随版本发布；0.4.0 期间有用户在 Apple 芯片机器上实际安装使用过，
  0.4.1 起没有再做过真机安装验收。x64 安装包随版本发布，但还没有在 Intel 真机上验收。
- **Windows / Linux**：Electron 代码理论上可以运行，但尚未做端到端验证。请按实验性支持对待，并报告
  具体失败。

安装验收逐条记在[安装验收记录](../development/install-verification.zh-CN.md)，那里没有记录的平台就是没验收。

## 模型兼容性

智能体运行时要求 Claude Code 兼容的模型路由。模型服务可以暴露不同协议；不是所有能用于普通聊天的
模型都能在智能体里选择。模型不可用时，智能体页会说明是供应商停用、缺少 API Key、模型未启用，还是
运行时协议不兼容。

限流、超时和临时网络故障不等于端点不兼容。应用会保留模型可选，并把兼容性标为“未验证”，而不是
直接隐藏。

## 数据与隐私限制

- 数据是本地存储，但不是整体加密。请保护操作系统账号和 `userData` 目录。
- 供应商凭据走平台密钥库；渲染层只拿到掩码预览。
- 备份和迁移由用户负责。参见[隐私与安全](../platform/privacy-and-security.zh-CN.md)。
- MIT 许可证只覆盖代码，不覆盖第三方数据。参见[数据与第三方服务](./data-disclaimer.zh-CN.md)。
- 产品不是托管服务，没有账号找回。

## 网络与代理限制

- 代理模式默认跟随系统代理。如果系统里还留着一条连不通的旧代理，新装用户的出站请求会先走它，
  然后失败。这种情况应该在「测试代理」里能看清失败原因：它要指出连不通的是系统代理，而不要把
  「系统代理连不通」误报成「模型服务挂了」。

## 产品限制

- 市场情报是决策辅助，不是投资建议。
- 没有下单、组合管理或券商连接。
- 分析质量取决于用户配置的来源、凭据和数据。
- 来源缺失时会明确暴露缺口，不会静默替换。
- 智能体选择页目前没有入口：打开**情报**直接落在看板。

### 消息、解读与通知

- 按条 AI 解读只由读者手动发起，结果只留在那条新闻的详情里，不进最新结论卡、不进分析时间轴、也不进日报。
- 同一条新闻最多只有一份解读：已经有时再点显示「查看 AI 解读」，不会重跑出第二份。
- 新闻强度分五档：1 与加密市场无关、2 圈内单资产且无外溢、3 影响整体风险偏好或一类资产、4 直接影响 BTC/ETH 的资金流或供需、5 可能改变趋势的冲击。这把尺子只量新条目，**已有的历史评分不会重算**。
- 桌面通知的强度门槛是「中」（三档里的中间那档），免打扰时段不发。**「还没有判定」不等于「低」**：未判定的条目不出现在舆情列表里、不推桌面，也不能发起解读。

### 事件总线的存储文件

事件总线的记录存在应用数据目录里的一个文件中。这个文件如果坏了，或者是更新的版本写的，
**应用会停止写它，而不是把它换掉**：发布事件会明确失败，文件里已经有的内容一个字节都不动，
也绝不会自动修复、自动改名或自动覆盖。

- 文件里已有的记录不会丢，我们把它原样留着，等有人来处理。
- 在这期间发布的事件**不会落盘**；调用方拿到的是错误，而不是一句「已保存」——不会有东西悄悄消失。
- 唯一的出路是人工把那份文件挪到一边、重新开始。应用不替你做这一步，因为那等于替读者决定
  「这些数据不要了」。
- 判断到底是「文件本身被拒」还是「新功能自己写失败」，第一步看事件总线诊断：里面的
  `integrity` 与 `blocked` 会说清是哪一种。看清之后再决定回退还是修。

## API 与配置稳定性

`0.4.5` 不承诺内部 API、数据库 schema 或设置结构的稳定性。升级前请备份 `userData`。在公开接口
稳定之前，产品 manifest 和平台契约可能在小版本之间变化。

## 报告问题

报告 bug 时请包含：

- 操作系统和版本；
- 应用是从源码启动还是安装包；
- UI 上的完整错误文本；
- 相关本地日志，且已移除凭据和个人路径。
