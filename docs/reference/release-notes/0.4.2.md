# MacroBay 0.4.2

What changed for the people using the app, and what to look at before you upgrade a copy you already
run. For what the app can and cannot do at all, see [Status and limitations](../status-and-limitations.md).

## Download

- macOS · Apple Silicon: `MacroBay-arm64.dmg`
- macOS · Intel: `MacroBay-x64.dmg`

**Intel build status.** The Intel build is `MacroBay-x64.dmg`: **it is built by the release workflow,
but it has not been verified on Intel hardware yet.** The Apple Silicon download link is unchanged,
and `latest-mac.yml` is produced only by the arm64 job.

The build is unsigned and not notarized, so the first launch still takes the two steps below.

## Read this before upgrading

1. **This build is neither code-signed nor notarized.** The first launch takes two steps: on macOS, drag
   the app into Applications, then **right-click (or Control-click) → Open** and confirm — a plain
   double-click is stopped by Gatekeeper. On Windows, run the installer and choose **More info → Run
   anyway** in SmartScreen. **Both steps are needed again after every downloaded update.**
2. **The official calendar from the U.S. Bureau of Labor Statistics is still unreachable** (the endpoint
   returns 403), so automatic sync stays off. What is already in the calendar is frozen at the last
   successful sync, and those events **carry no publication time** — we do not print a time we made up.
   Your data is not deleted.

## What you will see

### Phone alerts: analysis conclusions now actually reach you

- **Before, only one kind of trigger sent an alert**: analyses that reached a threshold — news items,
  data surprises — ran and published but never reached your phone. Now **every threshold-triggered
  analysis sends one alert**; the same event still alerts only once, and the daily cap still applies.
- When a push cannot go out, the record names which reason it was (no channel connected, more than one
  connected, channel type cannot deliver, credentials missing, not enabled) instead of one vague sentence.
- **"Send test notification" no longer fires repeatedly when you click it again**: the button is disabled
  while a request is in flight, and within 10 seconds after a success another click only shows a hint. A
  failure does **not** start a cooldown, so one failure cannot block your retry.
- **Telegram reconnects on its own**: a dropped connection used to leave one failure row and then silence —
  you could not tell "retrying" from "gave up", and pushes quietly stopped. It now shows "cannot reach it
  right now, retrying automatically", writes "receiving messages again" once it reconnects, and after about
  15 minutes of failed retries stops with a plain sentence: automatic reconnect stopped, check the network
  or proxy and enable the channel again.

### Daily briefing: when the model cannot write, your data is still there

- **When the model is unavailable, rate-limited, timed out or has no key**, the edition still publishes the
  factual layer and says that the AI editorial was not generated, and why. The attempt is recorded as a
  failure at the same time, so you can tell this is a failed edition rather than a quietly shipped
  template that looks complete.
- Three explanations cover three situations: **not configured yet** (go to settings), **not written this
  time** (generate again), **quota used up** (no button in the sentence, and no recovery time we do not
  know).
- **If another language slips into an edition, it is rewritten once; if it still happens, the whole edition
  is not published.** You see the failure row and the reason, and you can retry. No paragraphs are dropped
  and nothing is auto-translated.
- **When the macro column cannot read the calendar it says "not readable right now: reason"**, the same
  sentence used in the "data gaps and limits" column. If the day genuinely has no events, nothing is
  printed — "cannot read" is never written as "there is none".
- **The stale row no longer says "went back"**; it says the data is stale and reuses the previous trading
  day, naming which day that was.
- **When a news headline is not in the edition's language, it is marked "original"**, and the copied text
  carries the same marker.
- **Copied text now matches the page**: the BTC/ETH rows add "perpetual", and the Nasdaq proxy row adds
  "(QQQ perpetual proxy)".
- **The edition you opened no longer snaps back to the default one when a run finishes**: a scheduled or
  background run ends, and the page stays on the edition you were reading; if it failed, it gets its own
  failure row rather than "no briefing this time".
- **"A dense day" is no longer just a string in the copy table**: on a day that exceeds the cap, the
  briefing says so, on the poster and in the copied text as well.

### Calendar: not one blank block, but three situations

- **The permanent explanation rows at the top moved into the question mark**, leaving the current status
  and the colour legend in the body.
- **Event details no longer squeeze the calendar**: the details float above it without a scrim, the month
  column keeps its width, and you can keep clicking the next event.
- **Details now carry two moments**: when the record **first reached the database**, and when the released
  value **was first obtained**. The second is not a publication time — they are often hours apart.
- **Empty pages split into two**: when no calendar source is enabled it says "no calendar source is
  enabled" and offers "enable one"; when the month genuinely has no events it says "no events this month"
  and gives **no button** (there is no wider scope to expand, and month navigation is already in the
  header).
- **When a source has no English items, it says "this source provides no English items"** instead of
  calling it "no events this month".

### Settings: you can adjust how a source behaves

- **Each source now has "collection policy"**: enabled, collection cadence (manual / balanced / high),
  scope policy (all / watchlist first / holdings first), and whether to include it in sentiment analysis.
  Changes save immediately; a failed save keeps the value you just picked and offers a retry.
- **New "default coverage"**: decides which markets the dashboard covers (global macro and digital assets
  by default, seven categories selectable).
- **Source rows no longer pretend to be clickable**: clicking used to do nothing; it is now an explicitly
  non-interactive row.

### Session list: one scrollbar, and no identifiers in names

- **The sidebar now has a single scrollbar**: the automatic-session block used to sit outside the list,
  got pushed out of view once there were many rows, and could not be scrolled to at all (most visible with
  41 rows). It now scrolls with the list.
  The trade-off, stated plainly: the collapsed "automatic sessions" summary no longer stays pinned to the
  bottom of the panel — you have to scroll to the end to see it.
- **Session names no longer show internal identifiers**: early automatic sessions stored a run identifier
  as the name; those now show "Untitled session", while normal sessions show the module name. Sessions you
  named yourself are untouched.

### Your data is harder to lose now

- **One class of bug made records vanish**: when a file could not be read, the old behaviour treated it as
  "empty" or as "you never configured this", then wrote defaults back over it. This version **says it could
  not read the file, refuses to overwrite it**, and keeps an unmodified copy first. It covers briefing
  history, past judgements, settings, briefing AI settings, the push threshold and calendar reminders.
- **Records that come back**: briefing history that an earlier upgrade hid is readable again. Nothing about
  the content changed — it simply could not be read before.
- **A broken sentiment store is no longer rebuilt from scratch on its own**: a copy is kept first, and the
  new store is created only when you ask for it.

### Time and state no longer tell two stories

- **A clock with a time zone no longer prints its offset twice** (readers outside UTC used to see
  `GMT+8 GMT+8`), and dates and times follow the time zone you set.
- **One missing series no longer makes the whole block disappear**: funding-rate history and capital
  readings show the series that is available, and mark the other one "unknown" with a reason.
- **"This data comes from another version" no longer hands you a retry button that cannot work**; it says
  plainly that you have to quit the app completely and open it again.

### Notification centre and run records

- **Records no longer disappear after restarting the app**: a record that carries only finished sentences
  and no legacy body is no longer treated as "no body" and dropped on load.
- **A delivery stopped by a rule is no longer painted as a red failure**: platform rate limiting counts as
  "not sent by rule" and is kept apart from "delivery failed".
- **Run records are stored per language**: an edition run in two languages is two records, not one
  overwriting the other.
- **The failure row shows the run's nominal cutoff**, not when it was started or re-run — re-running the
  07:00 edition no longer prints 09:30.

## Known limitations

- **Whether a conclusion was right is still undecided**: scoring a conclusion needs a grading capability
  that this version does not have.
- **The official calendar from the U.S. Bureau of Labor Statistics is unreachable** (the endpoint returns
  403); see [Status and limitations](../status-and-limitations.md).
- **The channel list only shows channels that work**: WeCom, Feishu, QQ and Discord are not implemented and
  have been removed from the "channels" settings rather than left as selectable placeholders — better to
  have nothing in the list than an entry you cannot switch on.
- **Linux is not packaged**, and **the Intel build has not been verified on Intel hardware**.
- **Messages sent back from your phone are not shown**: this version confirms outbound delivery only;
  showing inbound messages needs a minimal inbound surface, which is not part of this release.
- **One alert per story; an escalation does not send a second one**: if a story already reached your phone
  as "medium" and later reporting rates it "high", no second notification is sent. What you miss is the
  escalation alert itself — the story stays in the app with the latest report's rating. The
  notification-centre record, too, keeps the strength it had on first delivery.
- **There is no auto-update channel**: the version hint only tells you a new version exists; downloading
  and installing is still up to you.
