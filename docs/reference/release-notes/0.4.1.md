# MacroBay 0.4.1

What changed for the people using the app, and what to look at before you upgrade a copy you already
run. For what the app can and cannot do at all, see [Status and limitations](../status-and-limitations.md).

## Before you upgrade

1. **This version is not code-signed and not notarised.** First launch takes two steps. On macOS,
   drag the app into Applications, then **right-click (or Control-click) → Open** and confirm
   **Open** — double-clicking is blocked by Gatekeeper. On Windows, run the installer and choose
   **More info → Run anyway** in the SmartScreen dialog. **Both steps repeat with every downloaded
   update.**
2. **The official BLS calendar can no longer be fetched from this network.** The site answers 403
   here, so automatic syncing for that one calendar is switched off. Events already in your library
   come from the last successful sync (22 October 2026) and carry **no release time**. Nothing of
   yours is deleted; when the source is reachable again, syncing can come back.

## What's new

### Phone push works again — and when it fails, it says which kind of failure it was

- For a while almost nothing reached a phone: the delivery path was never handed the channel to use,
  so every attempt failed as "no channel" while the channel itself was fine — the channel page's own
  test message went through, which is exactly what made it look like the channel was at fault.
  Pushes, re-sends and the test buttons now share one resolver, so all three work again.
- **The three test buttons in a product's own notification settings really send now.** Before, the
  request they build was missing a list that submission always reads, so it was refused before
  anything left the machine.
- **When a push cannot go out, the record says which kind it is**: no channel connected, more than
  one enabled, the channel's adapter cannot carry notifications, its credentials are missing, or it
  is not enabled. One sentence for five different causes was why "no channel available" was unhelpful.

### Notifications keep their records and their reasons

- **Records no longer disappear on reload.** Notifications that carried the finished sentence but no
  older copy key were judged as having no text when loaded, dropped, and the drop was then saved
  back — so they were gone for good. Any record with either form of text is kept now.
- **The reason a notification was held back is written down.** It was produced and then swallowed
  before reaching the log, which is why a day with "almost no push" could not be explained. The log
  now carries the reason, the event and the sender — and only those kinds of fields.

### A recovered analysis no longer goes silent

The "analysis recovered" notice was refused on **every** submission, because the request was missing
a list that the delivery path always reads; it appeared nowhere and nothing said so. Every kind of
analysis notice now carries it, and the shortcut that hid the mistake at compile time is gone.

### Calendar: a stopped source looks stopped, a month that could not be read says so, and you choose the countries

- **The stopped BLS calendar no longer looks healthy.** Its refresh is greyed out and says why,
  instead of showing a source that will never update as if it were fine.
- **A month the app could not read says "could not read", not "nothing here".** The two used to look
  the same, which is how a network failure read as an empty month.
- **A source that is unavailable is no longer drawn as healthy** anywhere it is listed.
- **You can choose which countries the calendar reports.** It is one row in the calendar's
  notification settings; the default stays the United States, and if you never touch it nothing
  changes.

### Home: the latest AI conclusion keeps a way out

- If the detail cannot be read, the card says so and offers **"try again"**, instead of a panel that
  cannot be left and never reads again.
- **Retrying only reads again**: it does not run the analysis a second time and does not spend an
  analysis call.

### Smaller, still visible

- **The sentiment push threshold is yours to set**: weak, medium or strong, default medium — the
  same behaviour as before until you change it.
- **A quiet news source gets a weekday 12-hour and weekend 24-hour window**, and the row only says
  "no new items in this window". It no longer guesses that a source stopped publishing.
- **A missing calendar expectation has three separate answers** — not published, not known yet, or
  could not be read — instead of two of them being merged into one.
- **A failed briefing no longer states a duration it cannot know**, and a turn that stopped says
  which of three things happened rather than one word for all of them.

## Known limitations

- **The installed Windows build still has not been checked on real hardware**: the installer
  walkthrough, shortcuts, notifications and taskbar grouping are all unverified.
- **The enterprise WeChat channel is a placeholder** and always fails at runtime. The other five
  (Telegram, Slack, Lark, Discord, QQ) are real implementations.
- **We are not scoring whether calls were right yet**: grading a call needs a scoring capability this
  version does not have, so no accuracy figure is published — not one call has been graded.
- **BLS calendar events carry no release time** until the official source is reachable again.
- **There is no automatic update channel**, and Linux is not packaged. The update notice only tells
  you a newer version exists; downloading and installing stay yours to do.
- On Windows the tray icon is created from an empty image and is invisible; "open with another app"
  is macOS-only.
