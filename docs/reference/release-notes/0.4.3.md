# MacroBay 0.4.3

What changed for the people using the app, and what to look at before you upgrade a copy you already
run. For what the app can and cannot do at all, see [Status and limitations](../status-and-limitations.md).

## Download

- macOS · Apple Silicon: `MacroBay-arm64.dmg`
- macOS · Intel: `MacroBay-x64.dmg`

**Intel build status.** The Intel build is `MacroBay-x64.dmg`: **it is built by the release workflow,
but it has not been verified on Intel hardware yet.** The Apple Silicon download link is unchanged,
and `latest-mac.yml` is produced only by the arm64 job.

The build is unsigned and not notarized, so the first launch still takes the two steps below.

## Read this before upgrading

1. **This build is neither code-signed nor notarized.** The first launch takes two steps: on macOS, drag
   the app into Applications, then **right-click (or Control-click) → Open** and confirm — a plain
   double-click is stopped by Gatekeeper. On Windows, run the installer and choose **More info → Run
   anyway** in SmartScreen. **Both steps are needed again after every downloaded update.**
2. **The official calendar from the U.S. Bureau of Labor Statistics is still unreachable** (the endpoint
   returns 403), so automatic sync stays off. What is already in the calendar is frozen at the last
   successful sync, and those events **carry no publication time** — we do not print a time we made up.
   Your data is not deleted.
3. **An older briefing schedule is repaired, not wiped.** The upgrade only moves data: the old file is
   opened read-only and neither deleted nor modified, and if writing the new data fails the whole step is
   abandoned and retried next time. The migration splits the old "also generate an English edition"
   setting into a period of its own, so both editions are there; **after the upgrade every period carries
   its language, and none disappears from the list for a missing field**.
4. **Editing one period no longer touches the others.** Adding, editing or deleting a period touches only
   that row (the other rows are written back unchanged); a row this build cannot read stays in the file —
   such rows are not shown in the settings page yet, but they are not deleted.
5. **Two platform-side switches are prerequisites.** For Discord, open **Message Content** for this bot in
   the developer portal first, or the gateway refuses the connection — that is not an adapter fault. For
   Slack, turn on **Socket Mode** on the app side. Both live in the platform's backend, not in the app.

## What you will see

### Sources: one row answers four questions

- **Each source's detail grew a four-cell health block**: whether it has a reading today, when it last
  succeeded, why it is not collecting, and whether it can run right now. All four come from the same
  read, and the page does not work them out again — so the dot in the catalog and the pill in the detail
  cannot contradict each other.
- **When the fourth cell answers "yes", a "Run now" appears there**: the button is disabled while it
  runs, the same row says only "running" (a screen reader hears it too), and the "it resumes by itself"
  sentence moved into the ⓘ beside it. The result stays on that row — the server's summary on success,
  the reason when it fails — instead of flashing and disappearing.
- **Unreadable is unreadable, not "no data"**: a failed read shows an error state with a retry, and the
  retry re-reads this one source. Calendar-style sources only have per-provider runs and no per-run
  records, so two cells say "unknown" and explain why.
- **Source health went from "it lights up but never changes colour" to five tiers**: healthy, repeatedly
  failing, stale, failed and disabled are now distinguishable, and the catalog dot and the detail pill
  read the same judgement. Colour never carries it alone — ring versus filled is a difference in shape.
- **An unavailable source keeps a "read-only for now" tag on its collapsed header**: the full reason
  still sits on the first line of the expanded row, and the collapsed header no longer pretends it can
  be edited.
- **The top banner now says exactly one thing**: "configured, but still not connecting". "Not configured
  yet" is a pill instead, so the two states no longer look alike.
- **Greyed-out reason codes moved into the question mark**: the body keeps the human sentence (why the
  official calendar cannot be fetched), and the technical reason lives in the ⓘ right next to it.
- **Two places editing the same setting no longer overwrite each other**: after a save elsewhere this
  one re-reads by itself; while you have input you are editing it is not overwritten, and a line at the
  top says another place changed these settings and your input is untouched, with "reload" and "keep
  editing" offered.

### Daily briefing: a foreign-language paragraph now costs the whole edition

- **When another language slips into an edition, it is rewritten once** (it used to spend all three
  rewrites on the same paragraph); if it still happens, **the whole edition is not published**, and you
  see the failure row and the reason and can retry. No paragraphs are dropped and nothing is
  auto-translated. The judgement looks at the writing system (Chinese text in an English edition,
  English paragraphs in a Chinese one), not at sentence patterns or word lists.
- **Each edition's language line grew an "open session" at its end**: it appears only when the session
  that produced that edition in that language still exists; clicking it lands on that session, and if
  the session is gone it says so in place instead of navigating. Deleting stays in the context menu.
- **Older editions without a session to open show no such action** — that is deliberate, not an
  omission: there was never a session to open.

### Notifications and channels: test buttons, and run records

- **Sentiment alerts, calendar · before start and calendar · after release now have a "test" button
  underneath**: it really submits, really goes through the phone channel and really leaves a record;
  the success line is "sent to {channel} (test)" — if nothing went out, it does not say that. When
  there is not exactly one usable channel the button does not appear (it is not greyed out); when
  several are usable it refuses and says how many there were at that moment.
- **The other two (module-signal triggers and briefing complete) get no test button**: testing them
  would need a real business event as a carrier, and that fake event would show up in the notification
  centre under that event's name — better to have no button than a manufactured event.
- **Channel run records are read per channel, and how many are kept is capped**: the last **500** failure
  rows and **100** start/stop rows are kept, and cleanup runs **once a day** (03:04 in your local time
  zone). Anything older is deleted.
- **All five channels — Telegram, Slack, Discord, QQ and Lark — now ship their adapter, self-check and
  runtime.** "Self-check" here means **the checks exist in code, not that they have been run with real
  credentials**: each channel proves a different amount (Slack stops at obtaining a Socket Mode URL; Lark
  really opens a long connection and closes it). Sending and receiving with your own credentials is yours
  to verify. For Discord we did send one message through the script via the proxy — that is a REST send,
  **not the app's delivery pipeline**.

### Three settings that looked editable but did nothing

They share one shape: **the control exists, it saves, and nothing reads it** — or, the other way round,
a row is drawn that cannot be changed. Keeping them only made you believe the setting did something.

- **The "surfaces" row no longer lists "notification centre"**: it was never selectable, and the centre
  always records. That sentence now lives in the row's question mark, instead of a ticked,
  un-untickable control.
- **The channel create/edit drawer no longer has "permission mode" or "working directory"**: storing those
  two columns changes no behaviour — permissions come from the agent the channel is bound to, and the
  working directory from the agent workspace. **Values set before are unaffected**: the storage columns
  are still there and keep their values; the interface simply stops writing them.
- **The model service page dropped "more default model settings" and the "image model" beneath it**:
  the image generation path never read that default, so picking one did nothing. A value you already
  set is kept, not migrated, and not cleared by removing the control.

### Sessions: automation no longer pushes your own sessions down

- **The briefing's editor session no longer counts as one of your sessions**: it used to add a row on
  every generation, and the list was drowned within a day or two. Identity is now (edition × language),
  and historic copies are judged by field rather than guessed from names.
- **The market-analysis popup is no longer blank**: a session existed but opened empty (one system
  message); it now receives messages normally, and a failed write leaves a trace instead of silently
  becoming a blank panel.

### The dashboard's right column: three states, each with its own words

Those three rows say whether **this cell read just now**, not whether the source is good — so the words
changed from "available / unavailable" to "**read / could not read**".

- **The calendar row has three tiers**: schedule read / no schedule this month / schedule unreadable.
  "There genuinely is nothing this month" no longer shares a sentence with "the schedule could not be
  read" — the first is not a fault, the second is an error state with a retry.
- **Indices and positions gained a "slightly old" tier**: index stale · as of {time}, positions stale ·
  as of {time}. The value may still be right, but you can see how old it is; the judgement uses the same
  reading and the same threshold as the chart in the card, and the row neither judges again nor prints
  the threshold.
- **With only one leg available the cell does not turn red**: the positions row reads "positions read,
  funding-rate history has only one leg", naming what is missing and why.
- **A failed read is no longer drawn as "none"**: a failure is an error state with a retry; only a
  genuinely empty result is an empty state.

### When something goes wrong, the whole window no longer goes white

- **An error inside one panel stays in that panel**, and everything else keeps working; the error uses
  the shared state surface instead of blanking the whole window.
- **The positions card no longer reports "data is stale" backwards**: the judgement now uses the newest
  reading before the curve is folded; when the observation time and the newest reading differ it prints
  both ("01:00 · latest reading 01:45"), and one when they are the same.

## Known limitations

- **Whether a conclusion was right is still undecided**: scoring a conclusion needs a grading capability
  that this version does not have.
- **The official calendar from the U.S. Bureau of Labor Statistics is unreachable** (the endpoint returns
  403); see [Status and limitations](../status-and-limitations.md).
- **The channel list shows the channels this build implements**: whether one connects depends on your
  credentials, the platform-side switches and the network; this release did not verify each of them with
  real credentials.
- **Linux is not packaged**, and **the Intel build has not been verified on Intel hardware**.
- **There is no visible surface for inbound content**: all five channels can receive, but the app does
  not show what comes back from your phone; showing it needs a minimal surface first, which this release
  does not include.
- **"It sends" also holds only under your own credentials and network**: this release sent exactly one
  message, through the script, to Discord via the proxy.
- **When the briefing's macro section really has no high-impact event, it prints nothing**: that is
  deliberate, so the briefing does not read as if something went missing. The fact that the window was
  genuinely quiet is recorded in the gaps column on the right, marked as nothing to do.
- **One alert per story; an escalation does not send a second one**: if a story already reached your
  phone as "medium" and later reporting rates it "high", no second notification is sent. What you miss
  is the escalation alert itself — the story stays in the app with the latest report's rating.
- **Saving the same setting in two places overwrites it**: when both the configuration drawer and the
  settings page can edit the same item, the later save writes the whole document and can wipe a value the
  earlier save had stored. This version does not save per field. Editing the same item in two windows at
  once is out of scope for this version.
- **There is no auto-update channel**: the version hint only tells you a new version exists; downloading
  and installing is still up to you.
