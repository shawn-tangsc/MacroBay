# 模型服务

模型服务把 MacroBay 连接到为助手和智能体提供推理能力的模型供应商。配置完全在本地完成；MacroBay
不提供托管模型代理。

![模型服务](../assets/screenshots/settings.png)

## 概念

| 概念 | 含义 |
| --- | --- |
| 供应商 | 带端点和模型列表的厂商或中转服务 |
| API Key | 主进程调用供应商时使用的凭据 |
| 端点 | 供应商配置中按协议区分的 base URL |
| 模型 | 供应商提供的、具备聊天能力的模型 |
| 默认模型 | 助手或智能体没有显式绑定模型时使用的模型 |

供应商协议、base URL、端点细节属于预设数据。第一版 UI 只暴露 API Key、启用开关、模型列表、
连接测试和默认模型选择。

## 添加供应商

1. 打开 **设置 → 模型服务**。
2. 从列表选择供应商，或添加自定义供应商。
3. 填写 API Key。
4. 启用供应商。
5. 添加或启用至少一个聊天模型。
6. 为智能体和助手选择默认模型。

Key 会送到主进程，并保存在平台密钥库中。保存后渲染层只拿到 `hasApiKey` 和掩码预览，拿不到原始值。

## 协议兼容性

一个供应商可以暴露多种协议。普通聊天和智能体运行时的要求不同：

- **普通聊天**可以使用 chat-completions 或 responses 路由。
- **智能体运行时**要求 Claude Code 兼容的 Messages 路由。

智能体模型选择器只列出满足运行时约束的模型。如果模型没有出现，请检查：

- 供应商已启用；
- API Key 存在；
- 模型已在供应商模型列表中启用；
- 供应商声明了 Messages 端点；
- 模型没有下线。

限流、超时或临时网络故障不是协议不兼容。模型会保持可选，兼容性显示为“未验证”，而不是被隐藏。

## 连接测试

测试按钮检查普通连通性和协议支持。测试通过不代表每个模型都适合智能体运行时；最终以智能体模型
选择器为准。

## 修改默认模型

默认模型保存在应用设置中。新建助手和尚未绑定模型的智能体会使用它；已经显式绑定模型的智能体保留
自己的模型。

## 排查

| 现象 | 检查 |
| --- | --- |
| `provider-not-ready` | 供应商已启用、端点已配置、API Key 已保存 |
| `provider-missing` | 模型指向的供应商仍然存在 |
| `missing-api-key` | 重新保存 Key；密钥库可能读取失败 |
| `model-not-enabled` | 把模型加入供应商模型列表 |
| `model-incompatible` | 供应商声明 Messages 端点，模型也支持 |
| HTTP 401 / 403 | Key、账号状态或供应商权限 |
| HTTP 429 | 限流；稍后重试或换模型 |

## 隐私

- 保存后原始 Key 不会返回渲染层。
- 应用不会把 Key 写入日志或复制到剪贴板。
- 供应商请求通过平台网络适配器离开本机，因此配置的代理会生效。
