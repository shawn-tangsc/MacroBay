# Platform and products

MacroBay is split so that the desktop shell and the AI platform can survive without the bundled
market-intelligence product.

## The rule

```text
platform must not import products
products may import platform
apps/desktop-shell loads products through manifests
```

This is a dependency rule, not a folder convention. If the platform starts importing a product, the
product is no longer removable.

## What a product contributes

A product declares its contributions through a manifest. Depending on the product, those can
include:

- sidebar menu entries;
- settings panels;
- service bootstraps and IPC contracts;
- workspace pages;
- agent seeds and product tools.

The shell reads a generated registry:

```bash
pnpm generate:products
```

The generator writes `products/generated/*`. These files are ignored and regenerated by the
standard scripts.

## Removing a product

1. Delete `products/<product-id>`.
2. Run `pnpm generate:products`.
3. Start the app.

The shell should still start. Any page, menu item, or setting that belonged to the product
disappears with it. A remaining hard-coded import from `platform` or `apps/desktop-shell` means the
boundary is broken.

## Adding a product

A minimal product needs:

- `product.manifest.ts` — id, display name, pages, settings, agents, services;
- a service bootstrap if it owns background work;
- desktop pages if it has UI;
- tests for its contracts and projections.

Start from the existing product only to understand the contract, not to copy domain logic. Keep
product-specific prompts, data sources, and workflows inside the product.

## Shared code

Put reusable contracts and capabilities in `platform` only when at least one product actually needs
them and they are domain-neutral. Do not move product vocabulary into the platform to avoid a
circular dependency.

## Generated files

Do not edit `products/generated/*` by hand. It is a build artifact. If the registry looks stale,
run the generator and restart the dev server.
