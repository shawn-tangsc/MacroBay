# 状态药丸

一个已经尘埃落定的状态——「已启用」「数据偏旧」「读取失败」「更新中」「未启用」——用
`@platform/ui/components/status-pill` 的 `StatusPill` 渲染。不要再手写 `<span class="…">` 小片。

组件存在的理由：同样三个词被画了五处、两套局部实现，每套自己的字号和颜色。现在只有一种 11px
字号、一套档位。

点的尺寸只有一处来源——`.status-pill` 上的自定义属性；`statusPillDotSizeGuard.test.ts` 判两件事：形状规则里写死尺寸，或者页面样式表自己去改 `.status-pill__dot` 的大小。为了紧凑把点缩小，形状通道就退回只剩颜色，而界面上看不出任何异常。

## 组件给什么

| 导出 | 用来做 |
| --- | --- |
| `StatusPill` | 一行状态字 + 一个辅助圆点。 |
| `STATUS_PILL_TONES` | 闭集：`['ok', 'warn', 'bad', 'info', 'muted']`。 |
| `StatusPillTone` | `'ok' \| 'warn' \| 'bad' \| 'info' \| 'muted'`。 |
| `StatusPillProps` | props 类型。 |

```tsx
import { StatusPill } from '@platform/ui/components/status-pill'
```

源码：`platform/ui/components/status-pill/`。界面规格：
`docs-private/05-desktop/ui-audit/prototypes/2026-11-01-1b-stateview-iconbutton-statuspill.html` ③。

### Props

| Prop | 类型 | 必填 | 含义 |
| --- | --- | --- | --- |
| `tone` | `'ok' \| 'warn' \| 'bad' \| 'info' \| 'muted'` | 是 | 这一档的语气；第六档编译不过。 |
| `labelKey` | `string` | 是 | 状态字的**键**。组件内零文案、不引 i18n。 |
| `resolveText` | `(key: string) => string` | 是 | 调用方的文案解析入口。 |

没有 `size`、没有 `className`、没有点击。规格只给 11px 一档且禁止 9px；第二档等于在调用点
自己发明一套字号。

### 五档

| `tone` | 含义 | token（圆点 + 描边） |
| --- | --- | --- |
| `ok` | 工作中、已启用、已保存 | `--success` |
| `warn` | 数据偏旧、降级、需要看一眼——**不是**错误 | `--caution`（6px 空心环，描边 1.5px） |
| `bad` | 失败 | `--danger`（6px 实心方块，圆角 1px） |
| `info` | 进行中，或中性提示 | `--accent`（6×2 短横条） |
| `muted` | 关闭、暂停、未配置 | `--muted`（3px 小实心圆） |

**档位色落在圆点与描边上，字本身用 `--text-strong`。** 这是有意与「给字上色」不同：
`color: var(--danger)` 属于 `check:danger-color` 门禁只减不增的前景（深色下 3.25–3.94，正文门槛
4.5），而 11px 的药丸字就是正文。灰度下药丸仍然可读——字承担状态，圆点与描边只是加强。

**档位说的是「这个状态对读者有什么要求」，不是「听起来有多严重」。** 调用点选档位时，回答的只有这一个问题：

| `tone` | 对读者的要求 |
| --- | --- |
| `ok` | 不用管，它在正常工作 |
| `muted` | 不用管，它没在跑 / 已结束 / 是默认态 |
| `info` | 等它，正在发生 |
| `warn` | 该看一眼 |
| `bad` | **已经出错了**，读者会受影响 |

所以 `bad` 只给「已经出的错」。**「危险的设置」不是失败**——它靠文案和位置表达，不靠把状态染红；否则 `bad` 就同时有两个意思，而这正是我们一直在清的那种事。

**状态到档位必须查表，不许用带兜底的函数**：

```ts
const STATUS_TONE: Record<ChannelCatalogStatus, StatusPillTone> = { supported: 'ok', … }
```

对联合类型建的 `Record` 在新增取值时编译不过；而 `if (…) return 'ok'; return ''` 不会——它会在界面上渲染一颗无色的裸标签，而且没人会来报。**最坏的失败是安静地说错话。**

## 组件自己守的规则

- **必须有字。** 圆点是 `aria-hidden` 的装饰；把颜色关掉不能把状态一起关掉。没有纯图标药丸，
  也没有「只有点」的变体。
- **一个药丸一个档位，一共五档。** 不接受通过 props 传自定义颜色。
- **是 `<span>`，不是按钮。** 药丸是状态不是动作：「点击刷新」这种动词属于按钮。把药丸做成可点，
  只会让那个错误看起来像是有意设计。
- **五档的圆点形状两两不同，不只颜色不同。** 实心圆／空心环／方块／短横条／小实心圆，按档位一一对应；因为 `ok` 与 `info` 的色值主要差在色相，灰度或红绿色盲读者面前「同一时刻只出现一个状态」就等于没法比较深浅。颜色保留，形状是第二通道，两者都不许去掉。点取 6px（`muted` 3px）是有原因的：5px 上 1.5px 描边的空心环内孔只剩 2px，灰度里读起来就是实心圆——那个尺寸上的形状编码是装饰冒充编码。验收用灰度与红绿色盲模拟，五个点两两可分才算过；彩色截图不算，这次漏掉正是因为它。
- **`warn` 与 `bad` 互不借 token**——偏旧不是失败。
- **`labelKey` 必须是键。** 它是开区间（每个站点的状态词不同，平台枚举不出来），
  这条线由 `statusPillKeyGuard.test.ts` 守：`<StatusPill …>` 调用点如果传了句子、中文标签
  或已解析好的字符串，守卫报红。变量与常量按它们的定义判，守卫不替它们作证。
- **这个名字只属于平台组件。** `platform/` 之外再声明一个 `StatusPill` 就是撞名，同一个守卫
  会红。翻译设置页那个是 label+value 的计数徽标、不是状态，已经叫 `CountBadge`。

## 调用点的规则

- **最多 6 个汉字 / 12 个英文字符。** 超长不缩字号、也不静默截断；把细节移到药丸旁边或把词缩短。
- **同一行不许两个同档药丸。** 一行只放它需要的状态，不按列凑。
- **药丸里不放动词。** 「刷新失败」是状态；「点击刷新」是控件。
- 状态字从键经 `resolveText` 出；药丸里永远不出现字面量句子。

## 怎么验用了它的页面

1. **灰度**：把页面转成灰度，每个药丸仍只靠字就能认出是哪一档。
2. **字号**：DevTools 读到 `font-size: 11px`、`line-height: 1.5`。
3. **颜色**：圆点与描边每档只引用一个 token；组件样式表里 0 个字面色值。
4. **结构**：`<span>`，没有 `<button>`、没有 `onClick`。
